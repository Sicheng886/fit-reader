# 训练报告撰写规范

## 结构

1. **先结论**：开头用 2–3 句话给出总体判断（这次训练质量如何、当前状态如何、下一步该做什么），再展开依据。
2. **逐主题论证**：按强度分布、心率/漂移、间歇或爬坡质量、负荷位置等主题分段，每段先给判断再给数据。
3. **收尾给行动**：最后给出具体、可执行的下一步建议，数量控制在 2–3 条，宁精勿滥。

## 论证纪律

- **引用具体数据**：每个判断必须落到训练数据中的具体数值（如 "NP 178W / IF 0.84"、"Z2 占比 62%"、"心率漂移 7.2%"），禁止"强度适中""恢复不错"这类无数据支撑的套话。
- **区分事实与推断**：数据直接支持的写成事实；需要外推的（如"可能睡眠不足"）明确标注为推测，并给出验证方式。
- **建议必须可执行**：写到具体的强度（功率瓦数或 %FTP / 心率区间）、时长、频次（如"本周安排 2 次甜区，每次 2×15min @ 88–94% FTP，组间 5min"），不写"适当增加强度"这类空话。
- **指出缺失**：回答问题所需的数据不存在时，直接说明缺什么、如何补（如"缺少功率数据，无法计算 TSS"），不要用猜测填补。

## 可信度声明

- `anomalies` / `data_quality` 存在异常标注（功率缺失、记录缺口、心率跳变）时，先评估其对相关指标的影响再下结论，并在报告中声明受影响指标的可信度（如"20min 峰功率窗口含 45s 功率缺失，FTP 估算仅供参考"）。
- 单次训练样本量不足以下长期结论时，明确提示需要更多数据（可建议用户使用对话/工具查询历史趋势）。
- 骑手参数（FTP / 最大心率）疑似不准时（如功率-心率区间系统性偏移），指出并建议复核参数，而不是在不准的基准上继续推演。
